# 에이전트 기획안 — [업무 이름]

작성: [이름 · 부서] · 버전 v0.1 · 상태: 초안

> 이 파일은 **에이전트에게 주는 명세서**다. 사람이 읽기 좋은 문서가 아니라, 에이전트가 이 파일만 보고도 첫 동작을 만들 수 있게 쓴다.
> 대괄호 [ ]만 채운다. 모르는 칸은 비우지 말고 `〔모름〕`이라고 적는다 — 빈칸은 에이전트가 추측으로 메우고, 〔모름〕은 되묻는다.

## 0. 한 줄 요약

[누가] [무엇을 넣으면] → [무엇이] [어떤 형식으로] 나온다

예) 담당자가 `입력/` 폴더에 공고문 PDF를 넣으면 → 요건·일정·제출서류를 뽑은 요약표가 `산출/공고요약_날짜.md`로 나온다

## 1. 페인포인트 — 지금은 어떻게 하고 있나

- 현재 절차: [1단계] → [2단계] → [3단계] (손이 많이 가는 단계에 ★)
- 빈도 · 소요: [주 n회 · 회당 n분]
- 자주 나는 실수 · 불편: [ ]

## 2. 목표와 완료 정의

- 목표(한 문장): [ ]
- **끝났다는 것을 어떻게 아는가**(완료 정의): [예: `산출/` 폴더에 파일이 생기고, 표의 합계가 원본과 같고, 출처 링크가 전부 열린다]
- 하지 않는 것(범위 밖): [예: 발송은 하지 않는다 · 원본은 고치지 않는다]

## 3. 입력 자료

| 자료 | 위치 · 형식 | 예시 파일 | 공개 / 내부 | 비고 |
|---|---|---|---|---|
| [공고문] | [`입력/` · PDF] | [`입력/예시_공고.pdf`] | [공개] | [ ] |
| [ ] | [ ] | [ ] | [ ] | [ ] |

- **예시 파일을 `입력/`에 실제로 넣는다.** 실물이 없으면 에이전트는 가상의 형식을 상상해서 만든다
- 내부 자료는 개인정보·환자정보·비공개 문서를 뺀 것만 (반입 기준은 7절)

## 4. 산출물

| 산출물 | 형식 | 모양(예시) | 받는 사람 | 어디에 남기나 |
|---|---|---|---|---|
| [공고 요약표] | [md 표] | [`예시/정답_공고요약.md`] | [팀장] | [`산출/`] |

- **정답지를 손으로 하나 만들어 `예시/`에 둔다.** 에이전트가 자기 결과를 이것과 비교해 보고하게 한다

## 5. 처리 단계 — 에이전트가 할 일의 순서

| 단계 | 입력 → 처리 → 출력 | 쓰는 도구 · 자료원 | 사람이 서는 관문 |
|---|---|---|---|
| 1 | [PDF] → [본문 추출] → [텍스트] | [문서 도구] | — |
| 2 | [텍스트] → [요건·일정·서류 추출] → [표 초안] | [ ] | — |
| 3 | [표 초안] → [원문 대조 검증] → [검증 표] | [ ] | ★ 사람 확인 |
| 4 | [검증 표] → [저장] → [`산출/…md`] | [ ] | — |

- 관문은 **되돌리기 비싼 지점 앞**에 둔다 (목차 확정 전 · 발송 전 · 원본 덮어쓰기 전)
- 각 단계는 **입력과 출력이 파일**이어야 한다. 파일로 남지 않는 단계는 검증할 수 없다

## 6. 검증 항목 — 통과 기준

| 검사 | 방법 | 통과 기준 |
|---|---|---|
| [수치 원문 대조] | [산출 표의 숫자를 원문에서 다시 찾기] | [전부 일치, 하나라도 다르면 `〔불일치〕` 표시] |
| [출처 실재] | [링크 열어 보기] | [전부 열림, 안 열리면 `〔확인 필요〕`] |
| [형식] | [항목 수 · 글자 수 · 필수 열] | [ ] |
| [금지어 · 누락] | [ ] | [ ] |

- 검증을 통과하지 못한 결과는 **저장하지 않고 이유를 보고**한다
- 검증 항목은 나중에 `검수관` 서브에이전트의 검수 기준이 된다
